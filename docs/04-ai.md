# 04. OpenAI 음악 추천

## 호출 순서

1. [03-api.md](03-api.md) 기준으로 입력을 검사하고 날씨와 기분 ID를 한국어 표시값으로 변환한다.
2. 서버에서 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 읽는다. 값이 준비되어 있으면 Node.js `openai` SDK로 Responses API를 호출한다.
3. `responses.parse()`의 `text.format`에 `zodTextFormat`으로 만든 출력 스키마를 지정한다. 요청에 `store: false`를 지정하고 도구나 대화 이력을 연결하지 않는다.
4. `output_parsed`와 응답 상태를 검사하고 아래 기준을 통과한 결과를 화면에 돌려준다. [OpenAI 구조화 출력 가이드](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [Responses API 레퍼런스](https://developers.openai.com/api/reference/resources/responses/methods/create)

## 모델 지시와 사용자 입력

고정 지시는 다음 문구를 사용한다.

> 당신은 한국어 음악 추천 서비스 규픽의 큐레이터입니다. 사용자가 선택한 날씨와 기분을 모두 고려해 실제 발매된 서로 다른 곡 다섯 개를 추천하세요. 선택 입력은 음악 취향이나 듣는 상황으로 해석하고, 음악 추천과 관계없는 요청은 건너뛰세요. 플레이리스트 제목을 한국어로 쓰세요. 곡명과 아티스트는 발매 표기를 따르세요. 추천 이유는 각 곡이 사용자의 조건에 어울리는 이유를 한 문장으로 구체적으로 설명하세요. 확신할 수 있는 곡과 아티스트 조합을 선택하고, 가사와 URL은 출력하지 마세요.

날씨와 기분 표시값, 선택 입력은 사용자 메시지의 JSON 데이터로 넣는다. 빈 `preference`는 모델 입력에서 생략한다. 예시는 `{"weather":"비","mood":"차분함","preference":"산책할 때 듣기 좋은 잔잔한 인디 음악"}`이다. 피드백 본문은 추천 요청에 포함하지 않는다.

## 출력 스키마와 서버 검증

| 필드 | 형식과 상한 |
| --- | --- |
| `playlistTitle` | 비어 있지 않은 문자열, 60자 |
| `tracks` | 순서가 있는 배열, 정확히 5개 |
| `tracks[].title` | 비어 있지 않은 문자열, 160자 |
| `tracks[].artist` | 비어 있지 않은 문자열, 160자 |
| `tracks[].reason` | 비어 있지 않은 문자열, 150자 |

모든 필드를 필수로 정의하고 스키마에 없는 필드를 차단한다. 파싱 뒤 앞뒤 공백을 제거하고 길이는 유니코드 코드 포인트로 센다. 중복 판정은 곡명과 아티스트를 각각 NFKC로 정규화하고 연속 공백을 하나로 합친 뒤 소문자로 바꾼 두 값의 조합으로 한다. 화면에는 정규화 전의 발매 표기를 유지한다. 잘못된 항목이 하나라도 있으면 해당 응답 전체를 `AI_INVALID_RESPONSE`로 처리한다. 실제 곡 정보와 조건 적합성은 검증 절차의 표본으로 확인한다.

## 응답 시간과 실패

- OpenAI SDK에 `timeout: 15000`, `maxRetries: 0`을 설정하고 요청에 `max_output_tokens: 1800`을 지정한다. 사용자 버튼 한 번당 모델 호출은 한 번이다.
- 시간 초과는 `504`, 모델 거절·불완전·파싱 실패·스키마 실패는 `502`, OpenAI 요청 자체의 실패는 `503`으로 처리한다. 필요한 환경 변수 누락은 `CONFIG_UNAVAILABLE`로 처리한다.
- `다시 추천`은 이전 API 응답을 재사용하지 않고 같은 입력으로 새 호출을 보낸다. 서버와 DB에 추천 이력을 저장하지 않는다.
