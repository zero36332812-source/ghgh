# 규픽 UI 구현 지침

## 화면 구성

한 페이지에 헤더와 소개, 추천 입력, 추천 결과, 피드백 입력과 공개 목록을 순서대로 배치한다. 헤더에는 서비스 이름 `규픽 GyuPick`을 표시한다. 소개의 제목은 `오늘 날씨와 기분에 맞는 플레이리스트`, 설명은 `날씨와 기분을 고르면 지금 듣기 좋은 곡을 추천해 드려요.`로 작성한다.

페이지 전체를 한국어로 작성하고 문서에 `lang="ko"`를 설정한다. 추천 입력과 피드백 입력에 각각 섹션 제목을 둔다. 결과는 유효한 첫 추천을 받으면 추천 폼 바로 아래에 표시한다. 피드백 목록은 피드백 폼 아래에 둔다.

## 스타일과 반응형 레이아웃

CSS로 따뜻한 배경과 짙은 보라색 버튼을 구현한다. 아래 색상과 크기는 이 프로젝트의 기본 디자인 값이다.

| 항목 | 값 |
| --- | --- |
| 페이지 배경 | `#F8F5EF` |
| 폼·결과 카드 배경 | `#FFFFFF` |
| 본문·보조 텍스트 | `#251E33` · `#5E546B` |
| 기본 버튼·선택 상태 | `#5334A5` · `#EEE7FF` |
| 입력 요소 테두리 | `#827590` |
| 오류 텍스트 | `#9E2737` |
| 본문·줄 높이 | `16px` · `1.6` |
| 소개 제목 | `clamp(1.75rem, 5vw, 2.75rem)` |
| 콘텐츠 최대 너비 | `840px` |
| 좌우 여백 | 기본 `24px`, 너비 `600px` 이하에서 `16px` |
| 카드 안쪽 여백 | 기본 `24px`, 너비 `600px` 이하에서 `16px` |
| 카드 모서리·카드 사이 간격 | `16px` · `24px` |

한글을 표시하는 시스템 글꼴을 사용한다. 데스크톱에서는 날씨와 기분을 두 열에, 너비 `600px` 이하에서는 한 열에 배치한다. 선택 항목은 가용 너비에 맞춰 줄바꿈한다. 모바일에서는 추천과 피드백 제출 버튼을 카드 너비에 맞춘다. 너비 `320px`에서도 가로 스크롤 없이 모든 입력과 결과를 확인할 수 있게 한다. 긴 곡명, 아티스트명, 피드백은 카드 안에서 줄바꿈한다. 피드백 본문의 개행은 보존한다.

## 추천 입력

날씨와 기분은 각각 하나를 고르는 필수 항목이다. 첫 진입 시 두 그룹을 모두 미선택 상태로 둔다. 네이티브 라디오 버튼과 레이블을 사용하고, 각 그룹을 `fieldset`과 `legend`로 묶는다. 선택 상태에는 배경색과 함께 체크 표시나 라디오의 선택 표시를 사용한다.

| 표시하는 그룹 이름 | 옵션과 전송 값 |
| --- | --- |
| 오늘 날씨 | 맑음 `clear` · 흐림 `cloudy` · 비 `rain` · 눈 `snow` |
| 지금 기분 | 기분 좋음 `happy` · 차분함 `calm` · 울적함 `sad` · 피곤함 `tired` |

`듣고 싶은 음악`은 선택 입력이다. 힌트는 `예를 들어 산책할 때 듣기 좋은 음악`으로 표시한다. 앞뒤 공백을 제거한 뒤 유니코드 코드 포인트 기준 최대 100자이며, 글자 수와 한도를 입력란 가까이에 표시한다. 자바스크립트에서 `Array.from(값.trim()).length`로 계산한다. 한글 조합 중 입력을 보존하고, 한도를 넘으면 안내를 표시한 뒤 제출을 막는다.

| 상황 | 화면 동작 |
| --- | --- |
| 초기 또는 추천 조건 변경 | 기존 결과와 추천 오류를 지우고 버튼을 `추천받기`로 표시한다. |
| 필수 선택 누락 | 요청을 보내기 전에 `오늘 날씨를 선택해 주세요.` 또는 `지금 기분을 선택해 주세요.`를 해당 그룹에 표시하고 첫 오류 항목으로 초점을 옮긴다. |
| 선택 입력 한도 초과 | `듣고 싶은 음악은 100자까지 입력할 수 있어요.`를 표시하고 요청을 보내지 않는다. |
| 요청 중 | 폼의 입력과 제출을 일시적으로 잠그고 `추천을 준비하고 있어요.`를 표시한다. |
| 추천 성공 | 추천 결과를 표시하고 버튼을 `다시 추천`으로 바꾼다. |
| 첫 추천 실패 | 입력을 유지하고 API 오류 안내를 표시한다. 응답을 받지 못하면 `추천을 불러오지 못했어요. 다시 시도해 주세요.`를 표시한다. 버튼을 `추천받기`로 되돌린다. |
| 같은 조건으로 다시 추천 실패 | 직전 성공 결과를 유지하고 첫 추천 실패와 동일한 기준으로 오류 안내를 표시한다. 버튼은 `다시 추천`으로 되돌린다. |

결과 카드 제목에는 `playlistTitle`을 표시한다. 응답 순서대로 곡 다섯 개를 순서 있는 목록에 배치하고 각 항목에 곡명 `title`, 아티스트 `artist`, 추천 이유 `reason`을 표시한다. 새 추천이 성공하면 카드 전체를 새 결과로 교체한다.

## 피드백 입력과 공개 목록

추천 영역 아래에 `서비스 피드백` 제목, 입력 폼, `최근 피드백` 목록을 순서대로 둔다. 입력란 레이블은 `피드백`, 제출 버튼은 `피드백 보내기`로 표시한다. 입력란 위에 `작성한 내용은 누구나 볼 수 있어요. 개인정보는 적지 말아 주세요.`를 항상 표시한다. 이름이나 연락처를 받는 입력란은 두지 않는다.

입력란 아래에는 앞뒤 공백을 제거한 뒤의 글자 수와 `500자` 한도를 표시한다. 유니코드 코드 포인트 기준 1~500자만 제출할 수 있다. 공백만 입력한 경우 `피드백 내용을 입력해 주세요.`, 한도를 넘긴 경우 `피드백은 500자까지 입력할 수 있어요.`를 표시하고 입력란으로 초점을 옮긴다.

| 상황 | 화면 동작 |
| --- | --- |
| 제출 중 | 피드백 입력과 제출을 잠그고 `피드백을 보내고 있어요.`를 표시한다. |
| 제출 성공 | 입력과 글자 수를 초기화하고 `등록했어요.`를 표시한다. 공개 목록을 첫 페이지부터 갱신한다. |
| 제출 실패 | 입력을 유지하고 API 오류 안내를 표시한다. 응답을 받지 못하면 `피드백 등록을 확인하지 못했어요. 다시 보내 주세요.`를 표시한다. 사용자가 다시 입력하거나 전송할 수 있게 잠금을 해제한다. |
| 목록 최초 조회 또는 갱신 중 | 목록 영역에 `피드백을 불러오고 있어요.`를 표시한다. 기존 목록은 갱신 첫 페이지가 성공할 때까지 유지한다. |
| 목록 조회 성공 | 서버가 보낸 순서로 20개씩 표시하고 끝까지 자동으로 이어서 불러온다. 다음 페이지는 같은 목록에 덧붙인다. |
| 목록이 비어 있음 | 첫 페이지가 성공했고 표시할 항목이 없으면 `아직 등록된 피드백이 없어요.`를 표시한다. |
| 목록 조회 실패 | 이미 표시한 행을 유지하고 `피드백 목록을 불러오지 못했어요.`와 `목록 다시 불러오기` 버튼을 표시한다. 버튼을 누르면 실패한 페이지부터 재시도한다. 잘못된 커서 오류에서는 첫 페이지부터 다시 읽는다. |

피드백을 등록한 뒤 목록 갱신에 실패해도 `등록했어요.`를 유지한다. 목록 재시도 버튼은 조회 요청만 다시 보낸다. 폼과 목록의 진행 상태는 각 영역에서 별도로 표시한다. 목록 항목에는 피드백 본문과 저장 시각을 표시한다. 시각은 `Intl.DateTimeFormat`의 `ko-KR`, `Asia/Seoul`, `dateStyle: 'medium'`, `timeStyle: 'short'`로 표시하고 `<time datetime="…">`에는 원본 시각을 넣는다. 피드백과 추천 응답의 문자열은 `textContent`로 화면에 넣는다.

## 키보드와 상태 안내

- 탭 키로 입력과 버튼에 차례대로 접근하고, 라디오 그룹 안에서는 방향키로 선택할 수 있게 한다. 버튼과 입력에 눈에 띄는 포커스 테두리를 적용한다.
- 조작 영역의 높이를 최소 `44px`로 두고, 입력란과 라디오의 레이블을 눌러도 해당 요소를 조작할 수 있게 한다.
- 오류 문구를 해당 입력과 `aria-describedby`로 연결하고 오류가 있는 입력에 `aria-invalid`를 적용한다.
- 요청 시작, 완료, 오류를 각 영역의 상태 텍스트로 표시하고 `role="status"` 또는 `role="alert"`로 알린다. 추천 성공 알림은 `추천곡 5개를 준비했어요.`를 사용한다. 자동으로 불러온 목록 전체를 매번 읽어 주는 동작은 피한다.

요청과 응답 형식은 [API 명세](03-api.md), 브라우저에서의 확인 절차는 [검증 지침](06-verification.md)을 참고한다.
